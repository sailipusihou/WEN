# Low Flame 上线部署指南

> 本文档说明如何把 Low Flame 商城部署到线上，以及上线后如何持续更新。

---

## 一、项目特征（决定部署方式）

| 项目 | 说明 |
|---|---|
| 技术栈 | Next.js 15 (App Router) + React 19 + TypeScript |
| 数据库 | **SQLite 本地文件** `data/site.db`（better-sqlite3） |
| 其他数据 | `data/*.json`（营销、促销、推荐、会话等，约 4.5 MB） |
| 上传文件 | `public/uploads/`（商品图、语音消息，约 117 MB） |
| 环境变量 | `.env.local`（PayPal 密钥、DATABASE_BACKEND、代理等） |

### ⚠️ 关键结论
1. **不能用 Vercel / Netlify / 静态托管**：这些平台没有持久磁盘，SQLite 数据库和上传文件会丢失。
2. **必须使用持久化服务器**：VPS 云服务器，或你自己的电脑 24 小时开机。
3. **代码与数据分离**：
   - 代码 → 走 git（`.gitignore` 已排除 `/data/` 和 `.env*.local`）
   - 数据 → 只存在于服务器本地，单独备份/同步

## 二、上线前置条件清单

### 🔴 必须完成
- [ ] 服务器（VPS 或本机常开）
- [ ] Node.js 20+ 安装（本项目使用 Node 24 开发）
- [ ] 代码推送到 GitHub（`git push origin master`）
- [ ] `.env.local` 配置到服务器
- [ ] `data/` 目录同步到服务器（SQLite + JSON）
- [ ] `public/uploads/` 同步到服务器
- [ ] 进程守护（PM2 或 systemd）—— 保证崩溃自动重启、开机自启
- [ ] 域名解析 + HTTPS

### 🟡 业务配置（影响功能完整性）
- [ ] **PayPal 切换到生产环境**：`paypalEnv` 改为 `production`，并替换为正式 Client ID / Secret
  （当前为 `sandbox`，客户无法真实付款）
- [ ] **SMTP 邮件配置**：当前完全未配置，订单确认/发货通知邮件无法发送
- [ ] **`siteUrl` 设置为** `https://lowflame.store`（影响 SEO 与社交分享卡片）
- [ ] 管理员密码确认（非弱密码）

### ⚠️ 构建注意事项
项目使用 `next/font/google` 加载 4 个字体：
`Playfair_Display`、`Inter`、`Noto_Serif_SC`、`Noto_Sans_SC`

**`npm run build` 时会从 `fonts.gstatic.com` 下载字体**：
- 海外 VPS：通常可直接构建 ✓
- 国内 VPS：可能无法访问 Google Fonts → 需要构建时挂代理，或改用本地字体

## 三、方案 A：现有电脑 + Cloudflare 隧道

### 特点
- 💰 成本：0
- 👎 电脑必须 24 小时开机；断电/重启/断网会导致网站不可访问（530）
- 👍 数据不用搬迁，可立即上线

### 部署步骤
```powershell
# 1. 生产构建
cd D:\2026-06-20\WEN
npm run build

# 2. 以生产模式启动（不要用 dev）
npm start          # 监听 3000 端口

# 3. 启动 Cloudflare 隧道（使 lowflame.store 指向本机）
cloudflared tunnel run lowflame
```

### 开机自启（PowerShell 计划任务）
把 `npm start` 和 `cloudflared tunnel run lowflame` 注册为计划任务（触发器：系统启动时）。

## 四、方案 B：VPS 云服务器（推荐）

### 特点
- 💰 成本：约 ¥30-70/月
- 👍 7×24 稳定、独立公网 IP、不依赖本地网络
- 推荐机型：2 核 2G 内存以上、40G 磁盘（含 117MB 上传文件 + 后续增长）

### 首次部署步骤（Ubuntu/Debian）

```bash
# 1. 安装 Node.js 20+
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs git

# 2. 安装 PM2（进程守护）
sudo npm install -g pm2

# 3. 拉取代码
sudo mkdir -p /var/www && cd /var/www
git clone https://github.com/sailipusihou/WEN.git lowflame
cd lowflame

# 4. 安装依赖
npm ci

# 5. 配置环境变量（关键！）
nano .env.local     # 粘贴本地 .env.local 内容（去掉 HTTP_PROXY/HTTPS_PROXY）

# 6. 同步数据（从本地电脑上传，二选一）
#    方式一：scp
scp -r data/ user@服务器IP:/var/www/lowflame/
scp -r public/uploads/ user@服务器IP:/var/www/lowflame/public/
#    方式二：打包后上传
tar czf lowflame-data.tar.gz data/ public/uploads/

# 7. 构建并启动
npm run build
pm2 start npm --name lowflame -- start
pm2 save
pm2 startup      # 按提示执行输出的命令，实现开机自启
```

### 域名与 HTTPS（Nginx 反向代理）

```bash
sudo apt install -y nginx
sudo nano /etc/nginx/sites-available/lowflame
```

写入：
```nginx
server {
    listen 80;
    server_name lowflame.store www.lowflame.store;

    client_max_body_size 30M;   # 允许上传图片/语音

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/lowflame /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 免费 HTTPS 证书
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d lowflame.store -d www.lowflame.store
```

### DNS 配置（Cloudflare）
在 Cloudflare 控制台为 `lowflame.store` 添加：
- `A` 记录 → 指向 VPS 公网 IP
- `www` 的 `CNAME` → `lowflame.store`
- 开启橙色云朵（代理）以获得 CDN 与 DDoS 防护
- SSL/TLS 模式设为 **Full (Strict)**

## 五、日常更新流程（核心）

### 一句话概括
**本地改代码 → git push → 服务器执行一条命令更新**。
数据在服务器上，不会被代码更新覆盖。

### 完整流程

```
① 本地开发电脑
   修改代码 → 测试通过
   git add -A && git commit -m "说明"
   git push origin master

② 服务器（SSH 登录后执行）
   cd /var/www/lowflame
   git pull
   npm ci                 # 依赖有变化时执行
   npm run build
   pm2 restart lowflame

③ 完成后线上生效（通常 30-60 秒）
```

### 一键更新脚本

在服务器创建 `/var/www/lowflame/deploy.sh`：

```bash
#!/bin/bash
set -e
cd /var/www/lowflame

echo "==> 拉取最新代码"
git pull

echo "==> 安装依赖"
npm ci

echo "==> 生产构建"
npm run build

echo "==> 重启服务"
pm2 restart lowflame

echo "==> 完成！网站已更新"
pm2 logs lowflame --lines 10 --nostream
```

```bash
chmod +x deploy.sh
```

以后更新只需在服务器执行：
```bash
/var/www/lowflame/deploy.sh
```

### 进阶：自动部署（可选）
配置 GitHub Actions，实现「本地 push 后服务器自动更新」，
无需每次登录服务器。需要额外配置 SSH 密钥与仓库 Secrets。

## 六、数据备份与同步

### 需要备份的内容
| 内容 | 路径 | 说明 |
|---|---|---|
| 数据库 | `data/site.db` | 商品、订单、用户、评论等 |
| JSON 数据 | `data/*.json` | 营销、促销、推荐、会话历史 |
| 上传文件 | `public/uploads/` | 商品图、语音消息 |

### 服务器端自动备份（建议每日）
```bash
# 创建备份脚本 /var/www/lowflame/backup.sh
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M)
BACKUP_DIR=/var/backups/lowflame
mkdir -p $BACKUP_DIR
cd /var/www/lowflame
tar czf $BACKUP_DIR/lowflame_$DATE.tar.gz data/ public/uploads/
# 只保留最近 14 天
find $BACKUP_DIR -name "lowflame_*.tar.gz" -mtime +14 -delete
echo "备份完成: $BACKUP_DIR/lowflame_$DATE.tar.gz"
```

```bash
chmod +x backup.sh
crontab -e
# 添加：每天凌晨 3 点备份
0 3 * * * /var/www/lowflame/backup.sh
```

### 把线上数据拉回本地（用于本地测试真实数据）
```powershell
# 在本地电脑执行（Windows）
scp -r user@服务器IP:/var/www/lowflame/data ./WEN/
scp -r user@服务器IP:/var/www/lowflame/public/uploads ./WEN/public/
```
⚠️ 注意：这会用线上数据覆盖本地数据，本地测试数据请先备份。

## 七、常见问题

**Q: 更新代码后网站没变化？**
- 检查 `npm run build` 是否成功（失败则不会更新）
- 检查 `pm2 restart lowflame` 是否执行
- 浏览器强制刷新（Ctrl+F5）清缓存

**Q: 网站显示 502 / 无法访问？**
- `pm2 status` 查看进程是否在运行
- `pm2 logs lowflame` 查看错误日志
- 检查 3000 端口是否被占用：`lsof -i:3000`

**Q: 上传图片/语音失败？**
- 检查 Nginx 的 `client_max_body_size`（建议 30M）
- 检查 `public/uploads/` 目录权限：`chown -R www-data:www-data public/uploads`

**Q: 构建时报字体下载失败？**
- 国内服务器无法访问 `fonts.gstatic.com`
- 解决：构建时配置代理，或改用本地字体（`next/font/local`）

**Q: 海外接口（Facebook/Instagram/X）调用失败？**
- 本地开发依赖 `.env.local` 中的代理配置（`HTTPS_PROXY`）
- 线上服务器通常可直接访问，**不要把本地代理配置带到线上**
