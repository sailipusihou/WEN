## 1. 项目概览

### 1.1 定位

营销中心是一个**一站式社媒运营工作台**，覆盖：

- 7 大社媒平台的**账号连接与管理**（Instagram / Facebook / X / LinkedIn / YouTube / Pinterest / TikTok）
- **AI 内容生产**（文案生成、配图生成、短视频生成）
- **统一收件箱**（评论聚合回复、私信聚合）
- **链接归因与转化追踪**（Referral 链接 → 点击 → 转化 → 营收）
- **实时运营状态**（SSE 推送评论/私信/提及）

### 1.2 设计目标

| 目标 | 实现方式 |
|---|---|
| 强大但不臃肿 | 10 个标签页按「工作流」组织，默认落在 Dashboard |
| 一眼看到状态 | 头部 LIVE/POLLING 实时徽章、平台能力状态矩阵 |
| 多角色适配 | 管理员看全量，普通员工只看自己的账号与数据（权限贯穿） |
| 可主题化 | 全部颜色走 CSS 变量，11 种面板风格一键切换 |

### 1.3 核心页面结构（单页 SPA 式）

```
Marketing Center（单个路由 /admin/marketing）
├── 头部 Hero（品牌图标 + 标题 + OPERATIONS CONSOLE + LIVE 徽章）
├── 胶囊标签栏（10 个 Tab）
├── 条件渲染的 10 个面板（activeTab === 'xxx' && (...))
└── 全局浮层（推送确认弹窗、AI 生成弹窗等）
```

## 2. 视觉设计系统

### 2.1 设计令牌（Design Tokens）

营销中心不写死颜色，全部通过 `--adm-*` CSS 变量消费（定义于 `app/globals.css`）。这是整个后台可主题化的根基。

**核心令牌（暗色示例 / 亮色示例）：**

```css
/* 暗色 */
--adm-bg: #111827;            /* 页面背景 */
--adm-sidebar: #0f172a;       /* 侧边栏 */
--adm-card: #1e293b;          /* 卡片 */
--adm-input: #334155;         /* 输入框 */
--adm-input-border: #475569;
--adm-text: #f1f5f9;          /* 主文字 */
--adm-text-secondary: #94a3b8;/* 次要文字 */
--adm-border: #334155;        /* 分割线 */
--adm-accent: #818cf8;        /* 品牌强调色（indigo） */
--adm-accent-bg: rgba(129,140,248,0.12); /* 强调色浅底 */
--adm-accent-text: #ffffff;   /* 强调色上的文字 */

/* 亮色 */
--adm-bg: #ffffff;
--adm-card: #ffffff;
--adm-accent: #6366f1;
...
```

**使用方式（行内样式为主）：**

```tsx
<div className="rounded-2xl p-5" style={{ backgroundColor: 'var(--adm-card)', border: '1px solid var(--adm-border)' }}>
  <p className="text-sm font-semibold" style={{ color: 'var(--adm-text)' }}>标题</p>
  <p className="text-xs" style={{ color: 'var(--adm-text-secondary)' }}>说明文字</p>
</div>
```

> 💡 **思路**：项目采用「Tailwind 管布局，CSS 变量管颜色」的混合模式。布局类（flex/grid/间距/圆角）用 Tailwind，颜色类（背景/文字/边框）全部用 CSS 变量行内样式。好处：**主题切换只改变量，组件零改动**。

### 2.2 主题体系（11 种面板风格 + 亮暗）

`globals.css` 中通过 `[data-admin-panel-style="xxx"]` 属性选择器**整体覆写**令牌：

| 风格 | 特征 | 关键差异 |
|---|---|---|
| `solid`（默认） | 扁平、干净 | 基础令牌 |
| `glass` | 玻璃拟态 | 卡片/侧栏半透明 `rgba(...,0.65)` + backdrop-blur |
| `cyber` | 赛博朋克 | 青色强调 `#00d4b4`、暗黑底 |
| `brutalist` | 粗野主义 | 硬边框 3px + 偏移硬阴影 `box-shadow: 5px 5px 0` |
| `gold` | 金色奢华 | 米色底、金色强调 `#e6c24a` |
| `matrix` | 矩阵绿 | 黑绿 `#00dd3a` |
| `holo` | 全息 | 紫罗兰渐变 |
| `mono` | 单色 | 红黑 `#e53e3e` |
| `midnight` | 午夜 | 深蓝紫 |
| `obsidian` | 黑曜石 | 纯黑 + 白字 |
| `noir` | 黑色电影 | 灰黑 + 灰白强调 |

**实现要点：**

```css
/* 面板风格 = 覆写同一组令牌，无需改任何组件 */
[data-admin-panel-style="brutalist"] {
  --adm-card: #ffffff;
  --adm-border: #111827;
  --adm-accent: #ea580c;
}
/* 配合强制样式让组件"听话" */
[data-admin-panel-style="brutalist"] [style*="background-color: var(--adm-card)"],
[data-admin-panel-style="brutalist"] [style*="backgroundColor: var(--adm-card)"] {
  background-color: var(--adm-card) !important;
  border: 3px solid var(--adm-border) !important;
  box-shadow: 5px 5px 0 var(--adm-border) !important;
}
```

> 💡 **思路**：即使用行内样式写颜色，只要值来自 CSS 变量，就能被属性选择器**以 `!important` 强制覆写**。这是「行内样式 + 可主题化」两全的关键技巧。

### 2.3 玻璃拟态（Glass）分层

后台布局读取设置项 `glassLayered / glassSidebar / glassTopbar / glassMenus / glassLists`，在 `<html>` 上打 `data-glass-*` 属性，CSS 侧用变量覆写为半透明 + 毛玻璃：

```css
[data-glass-layered="true"] {
  --adm-card: rgba(30, 41, 59, 0.65);      /* 半透明卡片 */
  --adm-sidebar: rgba(15, 23, 42, 0.7);
  --adm-input: rgba(51, 65, 85, 0.55);
  --adm-border: rgba(71, 85, 105, 0.5);
}
```

背景图 + 亮度/对比度/饱和度/暖度调节 + 覆盖层（overlay）叠加在根容器上，形成「背景图毛玻璃」效果：

```tsx
const bgFilter = `brightness(${bgBrightness}%) contrast(${bgContrast}%) saturate(${bgSaturation}%) blur(${bgBlur}px)`
```

### 2.4 科技感装饰（氛围层）

营销中心用少量「氛围组件」强化运营控制台的质感：

- **TechHud**：卡片四角描边 + 顶部扫描线动画（`scan-sweep`），纯 CSS 实现，`pointer-events-none` 不影响交互
- **LIVE/POLLING 徽章**：SSE 连接时绿色圆点 `animate-pulse` + 发光阴影，断线降级为灰色 POLLING
- **mono 字体标签**：如 `OPERATIONS CONSOLE`（`font-mono text-[10px]` 半透明胶囊）营造终端感
- **平台色徽标**：每个平台卡片用品牌色（Instagram `#E4405F`、TikTok 黑等）+ 对应浅底

```tsx
{/* LIVE 状态点 */}
<span className={`w-2 h-2 rounded-full ${sseConnected ? 'animate-pulse' : ''}`}
  style={{ backgroundColor: sseConnected ? '#22c55e' : '#9ca3af',
           boxShadow: sseConnected ? '0 0 8px #22c55e' : 'none' }} />
```

### 2.5 动效与反馈

- 按钮统一 `transition-all` + hover 变色/位移
- 选中 Tab：`backgroundColor: var(--adm-accent)` 胶囊反色
- 实时事件到达时，通知中心弹 toast（NotificationToast）
- AI 生成过程用 loading 骨架 + 轮询状态
- Framer Motion 用于前台商城页；后台以轻量 CSS 动效为主（**后台重信息密度，动效克制**）

## 4. 功能模块详解

### 4.1 Dashboard（运营总览）

- **快捷入口卡片**：Content Studio / AI Assistant / Social Accounts / Publish History（图标 + 描述 + 点击跳 Tab）
- **数据卡片**：本月触达、直接访问、转化订单、归因营收（数字 + 单位）
- **转化漏斗**：Story Entry → Bio Landing → Product Detail → Order（各环节访问量 + 转化率）
- **平台能力矩阵**（核心亮点）：每个平台一张卡，展示 Profile / Publish / Tracking / Insights 四项能力状态（`ready` 绿 / `partial` 黄 / `pending` 灰），以及账号数、发布数、点击/转化/营收

```tsx
const PLATFORM_SYSTEM_STATUS: Record<string, {
  profile: CapabilityStatus; timeline: CapabilityStatus;
  publish: CapabilityStatus; tracking: CapabilityStatus;
  insights: CapabilityStatus; comments: CapabilityStatus;
  messages: CapabilityStatus;
  nextAction: string;  // 平台下一步待办，直接展示给运营
}> = {
  instagram: { profile: 'ready', timeline: 'ready', publish: 'ready', ... },
  tiktok:    { profile: 'ready', timeline: 'ready', publish: 'partial', ... },
  ...
}
```

> 💡 **思路**：能力矩阵是「平台接入成熟度」的可视化体检表。`nextAction` 字段把工程师的 TODO 直接变成运营可见的下一步指引，是跨职能沟通的好设计。

### 4.2 Content Studio（AI 内容生产）

- **文案生成**：选择平台 + 产品 + 类型（social_post / ad_copy / product_desc / email_campaign）+ 语调（professional / casual / luxury ...）+ 模板（新品发布/闪购/产品故事/客户好评/节日/幕后）→ AI 生成标题、正文、话题标签、Hook、CTA、Tips
- **配图生成**：prompt + 尺寸 + 厂商模型选择 → `/api/marketing/generate-image` → 图片历史/裁剪/上传
- **视频生成**：`/api/marketing/generate-video` → 素材库
- **发布面板**：选择已连接账号 → 文案 + 媒体 → 直接发布（各平台 publish API）→ 记录到发布历史并生成归因链接

**交互细节**：右侧「属性面板」`rightPanelTab`（media / publish / settings）随上下文切换；生成结果可一键「带入发布面板」或「存入素材库」。

### 4.3 Social（账号连接与管理）

- **平台卡片**：品牌色图标 + 连接状态
- **OAuth 流程**（通用化）：
  - `GET /api/marketing/social-oauth?platform=xxx` 统一入口
  - 服务端生成 state（crypto 随机）+ PKCE code_verifier/challenge
  - `savePendingSocialOAuth` 暂存 → 回调校验 state → 换 token → 存账号
- **账号维度**：管理员可按员工查看/代连（`staffId` 筛选），非管理员只能管理自己的账号
- **健康检查**：`/api/marketing/instagram-health` 轮询、token 自动刷新（`lastSync` 55 分钟阈值）
- **Token 安全**：列表接口返回时脱敏（`hasAccessToken` 布尔，不返回明文）

### 4.4 Comments / Messages（统一收件箱）

- 跨平台评论聚合（Instagram / X / Pinterest / Facebook），统一列表 + 筛选 + 回复
- 私信聚合（Instagram / X / Facebook），会话视图（左侧联系人 + 右侧对话），支持 Emoji 选择
- **SSE 实时推送**：`/api/marketing/events/stream` 推 `comment / dm / mention / workflow` 事件 → 通知中心红点 + toast；断线自动降级为 15s 轮询
- Webhook 配置面板（Meta/Pinterest 订阅管理）

### 4.5 Referrals（归因链路）

- 每个发布内容生成专属 `?ref=xxx` 链接
- 前台 `trackReferralVisit` 记录会话 → 点击/转化/营收按平台、按员工聚合
- 归因模型选择（last_click / first_click）
- 扩展积压（EXTENSION_BACKLOG）：Story Link Taps、跨设备、多触点归因（产品路线图明示）

### 4.6 权限与多角色

- 导航与操作双保险：`canAccessNavItem(role, permissions, href)` 过滤导航；API 层 `requirePermission(req, 'messages_view' | 'social_publish' | ...)`
- 管理员 `isAdmin` 分支决定可见数据范围（全量 vs 自己的账号/链接/数据）
- 数据导出（CSV）、操作日志（Work Log）配套

## 5. 技术架构

### 5.1 单文件巨型组件的成因与对策

`page.tsx` 13,200 行是迭代自然长成的：每加一个平台/功能就在主组件里加 state + 面板。**它不是一个好榜样，但提供了大量可复用的模式**。新项目建议按标签页拆分（见第 8 节），模式不变、文件拆开。

### 5.2 状态管理（纯 React，无全局库）

```tsx
// 数据 state（全部 useState + 集中加载函数）
const [socialAccounts, setSocialAccounts] = useState<any[]>([])
const [socialContent, setSocialContent] = useState<SocialContentRecord[]>([])
const [referralLinks, setReferralLinks] = useState<ReferralLink[]>([])
const [allCommentsUnified, setAllCommentsUnified] = useState<any[]>([])
const [allConversationsUnified, setAllConversationsUnified] = useState<any[]>([])

// 派生数据（useMemo 计算，避免重复遍历）
const connectedVisibleAccounts = useMemo(() => ..., [socialAccounts, currentUser])
const platformCapabilityMatrix = useMemo(() => PLATFORMS.map(...), [...])
```

**加载模式**：`loadAll()` 用 `Promise.all` 并发拉取（`/api/marketing/social-accounts`、`/api/marketing/social-content`、`/api/referrals?stats=true`、`/api/settings`、`/api/products`…），进入页面触发一次；各面板进入时按需补拉。

### 5.3 实时通信（SSE + 轮询降级）

```tsx
// 事件流（EventSource）
const es = new EventSource('/api/marketing/events/stream?types=comment,dm,mention,workflow&platforms=...')
es.onmessage = (e) => { const ev = JSON.parse(e.data); handleSocialEvent(ev) }
// 断线 fallback：setInterval 15s 轮询 comments/messages
```

- `sseConnected` state 驱动头部 LIVE 徽章
- 服务端 `SocialEventBus` 单例管理订阅者，连接断开自动清理

### 5.4 平台抽象层（注册表模式）

```tsx
const PLATFORMS = [
  { id: 'instagram', name: 'Instagram', icon: Instagram, color: '#E4405F',
    bgColor: '#FFF0F3', url: 'https://instagram.com', loginUrl: '...' },
  { id: 'tiktok', name: 'TikTok', icon: MessageCircle, color: '#000000', ... },
  // 7 个平台同构
]
```

- 图标/品牌色/登录链接全部进注册表 → 平台卡片、账号选择器、统一收件箱**零分支渲染**
- 服务端 `PLATFORM_CONFIG`（`lib/` 与 API 路由）同构：enabledKey / clientIdKey / callbackUrlKey / authUrl / scope
- 新增平台 = 注册表加一行 + 平台专用 lib + API 路由，UI 层几乎不动

### 5.5 关键 API 契约（供后端设计参考）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/marketing/social-oauth?platform=` | GET | 发起 OAuth（state+PKCE，管理员可代员工） |
| `/api/marketing/social-oauth/callback?platform=` | GET | 回调换 token、存账号 |
| `/api/marketing/social-accounts` | GET/POST | 账号列表（脱敏）/ 连接、断开、验证 |
| `/api/marketing/social-content` | GET/POST | 内容记录（发布历史） |
| `/api/marketing/generate` | POST | AI 文案生成 |
| `/api/marketing/generate-image` | POST | AI 配图（mode/size/provider/model） |
| `/api/marketing/generate-video` | POST | AI 视频 |
| `/api/marketing/instagram-comments` 等 | GET/PUT | 平台评论/私信 |
| `/api/marketing/events/stream` | GET | SSE 实时事件 |
| `/api/referrals?stats=true` | GET | 归因统计（点击/转化/营收，按平台/员工） |
| `/api/marketing/instagram-health` | GET | 连接健康检查 |

### 5.6 安全要点（已落地）

1. OAuth state 用 crypto 随机生成，回调严格匹配，杜绝 CSRF
2. PKCE（S256）防授权码截获
3. 平台 token 服务端存储，接口返回脱敏
4. 权限贯穿：`requirePermission` + 账号归属校验（`canUserManageAccount`）
5. Webhook 签名校验（Meta 等）
6. 非管理员 OAuth 只能以自己的身份发起

## 6. 关键设计决策与经验教训

### 6.1 做对了的

1. **CSS 变量 + 属性选择器覆写** → 11 种主题零组件改动，换肤成本趋近于零
2. **平台注册表 + 能力矩阵** → 7 平台同构扩展，新增平台 UI 工作量最小化
3. **SSE + 轮询降级** → 实时体验与稳定性兼得，断线有明确视觉反馈（LIVE→POLLING）
4. **统一收件箱** → 跨平台评论/私信聚合到一个工作台，运营效率大幅提升
5. **归因闭环** → 发布→链接→点击→订单→营收全链路数据，让运营看到 ROI
6. **Token 脱敏 + 权限双保险** → 数据安全与多角色协作兼顾
7. **nextAction 字段** → 技术待办直接转化为运营可读的指引，减少沟通成本

### 6.2 踩过的坑（新项目避免）

1. **单文件 13,000+ 行**：任何改动都有回归风险，热更新变慢，多人协作冲突频繁 → 按 Tab 拆目录
2. **平台接入不齐时硬塞占位 UI**：X/TikTok 早期只有 alert 占位，体验割裂 → 用能力矩阵明示状态，UI 入口与能力匹配
3. **内联样式与 Tailwind 混用缺乏规范**：可读性差 → 新代码约定「布局 Tailwind / 颜色变量」
4. **OAuth 回调跳转目标分散**：各平台回调跳回地址不统一 → 统一回调后跳回发起页并带 `?platform_auth=success`
5. **幂等与竞态**：SSE 事件与手动加载并发更新同一列表 → 用 ref 防抖、以服务端时间为准
6. **代理环境不稳定**：海外 API（Meta/TikTok）在中国网络下需代理，接口错误要区分「网络不可达 503」与「鉴权失败 401」，避免误导用户重新登录
