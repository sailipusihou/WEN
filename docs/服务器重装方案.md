# 服务器重装方案（2026-09-17 制定）

> **背景**：`43.110.46.49`（lowflame.store）在 2026-09-15 被 root 级入侵，
> 当时仅做了应急清理；**2026-09-16 攻击者用一套全新路径再次进来**
> （门罗币矿机 + 两个伪装成内核线程的后门 ×2 + 四层持久化）。
> 这证明「清理」挡不住 —— 唯一彻底的办法是重装系统。
>
> 本次入侵的清除记录见 `scripts/deploy/contain-reinfection.cjs` 的注释。

---

## 一、要不要买新服务器？

**不需要。**

阿里云 ECS 自带 **「更换操作系统」**（也叫「更换系统盘 / 重新初始化系统盘」）：

- **免费**
- 约 10–20 分钟
- **公网 IP 不变** —— 域名解析、SSL 证书、备案都不受影响
- 会清空**系统盘**；如果有独立的数据盘，可选择是否保留（本项目不需要数据盘）

买新服务器反而更麻烦：换 IP 要改 DNS、重新签证书、可能涉及备案。

## 二、重装前：备份（**这一步不做，数据就没了**）

### 需要备份的东西

| 内容 | 服务器路径 | 为什么 |
|---|---|---|
| 数据库 + JSON 存储 | `/var/www/lowflame/data/` | 订单、商品、客户、营销、推荐……**不在 git 里** |
| 用户上传文件 | `/var/www/lowflame/public/uploads/` | 商品图、语音消息 |
| 环境变量 | `/var/www/lowflame/.env.local` | 基本为空（密钥多在数据库里），但备份一份 |
| nginx 站点配置 | `/etc/nginx/sites-available/lowflame` | 重装后要重建，有备份省事 |
| SSL 证书 | `/etc/letsencrypt/live/lowflame.store/` | 重新签发不难，备份可省一步 |

### 怎么做

已写好脚本，一条命令拉全（打包 → 下载 → 本地解压）：

```bash
cd D:/2026-06-20/WEN && SSH_PASS='服务器root密码' node scripts/deploy/backup-before-reinstall.cjs
```

输出到 `D:/2026-06-20/backups/pre-reinstall-<时间戳>/`。

**另外单独确认一次**（保险起见）：在阿里云控制台给这台实例**打一个快照**。
快照是整盘镜像，比文件备份更完整，而且随时可回滚。

### ⚠️ 备份出来的东西来自被入侵的机器

- **数据本身**（订单/商品/客户）照用
- **所有凭据一律视为已泄露** —— 见第五节的轮换清单
- **配置文件不要原样拷回新系统**，在新系统上重新配一遍更干净

## 三、重装前：先查阿里云账号本身

攻击者拿到了 root，要确认他有没有动过账号层面：

- [ ] **阿里云控制台密码**是否还是你的、有无异常登录记录
- [ ] **开启 MFA**（如果还没开）
- [ ] **有没有多出来的 ECS 实例** —— 攻击者常用你的账号开新机器挖矿
- [ ] **安全组规则**有没有被改（正常只该放行 22 / 80 / 443）
- [ ] **有没有异常的快照 / 镜像 / 密钥对**
- [ ] **账单**有没有异常（流量、按量实例）
- [ ] **RAM 子账号 / AccessKey** 有没有多出来的（有的话立刻删除）

> 这一步比修服务器更重要 —— 如果账号被控，重装多少遍都没用。

---

## 四、重装

1. 阿里云控制台 → ECS → 实例 → 选中 `43.110.46.49` → **停止实例**
2. 更多 → 磁盘和镜像 → **更换操作系统**
3. 选择：
   - 镜像：**Ubuntu 22.04 LTS**（与原来一致）
   - 登录凭证：**自定义密码**，设一个**强密码**（20 位以上，别用以前的）
   - 「保留数据盘」：本项目没有独立数据盘，不需要勾
4. 确认 → 等待重建完成（约 10–20 分钟）
5. 用新密码 SSH 登录，确认是新系统

## 五、重装后：先做安全基线，**再装应用**

> 顺序很重要 —— 先把门关好，再往屋里搬东西。

### 必做

| 项 | 做法 | 说明 |
|---|---|---|
| **强 root 密码** | 重装时已设 | 上次就是弱密码被暴力破解 |
| **fail2ban** | `scripts/deploy/step1-fail2ban.sh` | 密码试错 5 次封 1 小时，屡犯翻倍 |
| **ufw 防火墙** | `scripts/deploy/step3-ssh-firewall.sh` | 只放行 22 / 80 / 443 |
| **SSH 加固** | 同上脚本 | MaxAuthTries 3、关端口转发、LoginGraceTime 30 |
| **自动安全更新** | `scripts/deploy/step4-6-updates-rootkit.sh` | 漏洞自动打补丁 |
| **rootkit 扫描** | 同上 | rkhunter + chkrootkit |

### 建议这次顺手做

- **改用 SSH 密钥登录**（关掉密码登录）。上次被爆破就是因为开着密码登录。
  需要给 `scripts/deploy/ssh-run.cjs` 加密钥支持（现在只支持 password）。
- **建一个非 root 日常账户**，root 只用于运维。

## 六、重装后：部署应用

参考 `docs/上线部署指南.md`，要点：

1. **装环境**：Node.js 20+、PM2、nginx
2. **拉代码**：`git clone https://github.com/sailipusihou/WEN.git /var/www/lowflame`
3. **恢复数据**（只恢复这两样）：
   - `backups/pre-reinstall-*/data/` → `/var/www/lowflame/data/`
   - `backups/pre-reinstall-*/uploads/` → `/var/www/lowflame/public/uploads/`
4. **配 `.env.local`**：`DATABASE_BACKEND=sqlite`（**不要带本地的代理配置**）
5. **构建**：⚠️ 2GB 内存不能在本机跑 `next build` —— 用现在的
   **本地构建 → 上传产物** 方式：`node scripts/deploy/fast-deploy.cjs`
6. **nginx + HTTPS**：站点配置可从 `backups/pre-reinstall-*/lowflame` 参考，
   证书用 `certbot --nginx -d lowflame.store -d www.lowflame.store` 重新签
7. **后台配置**：Site URL、PayPal 生产凭证、SMTP、各平台 OAuth 回调地址

## 七、必须轮换的凭据（因为攻击者有过 root）

**这一项不能省。** 攻击者读过这台机器上的任何文件。

- [ ] **服务器 root 密码** —— 重装时已换
- [ ] **阿里云账号密码 + 开启 MFA**
- [ ] **PayPal Client Secret** —— 在 PayPal 后台重新生成
- [ ] **SMTP 邮箱密码**
- [ ] **后台管理员密码** —— 重装后用 `scripts/deploy/change-admin-password.cjs` 换
- [ ] **各社交平台 OAuth token**（Instagram / Facebook / X / LinkedIn / Pinterest / TikTok / YouTube）—— 在后台断开重连一次
- [ ] **GitHub 账号**（如果密码与服务器密码相同）
- [ ] **数据库里的其它密钥** —— 用 `scripts/deploy/list-credentials.cjs` 列出清单

以及：

- [ ] **核对 PayPal 有无异常交易**（这是 9/15 那份交接文档里就留下的待办）
- [ ] **核对客户数据有无被改动**（订单金额、客户邮箱）

## 八、如果决定继续不重装

那么这个前提必须接受：**机器随时可能再次被控**。

最低限度的持续措施：

- 每周跑一次 `scripts/deploy/diagnose-server.sh`，看 CPU 榜首和负载
- **部署突然连续失败 + SSH 静默丢包** = 很可能又是挖矿打满 CPU，
  先查 `uptime`，别只当网络问题
- 定期检查 `crontab -l`、`/root/.bashrc`、`/root/.profile` 尾部有无异常
- 用 `scripts/deploy/probe-server-settings.cjs` 的思路定期比对
